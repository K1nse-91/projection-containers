# 投影容器

Litematica 的 Fabric 客户端附属 Mod。沿用木棍选区，按容器查看位置、物品和数量。作者为 `K1nse_`。

## 安装

将 `build/libs` 中对应的 JAR 放入客户端的 `mods` 文件夹。同一游戏实例只放一份「投影容器」JAR。

| JAR 文件名 | Minecraft | 运行时 Java |
| --- | --- | --- |
| `container-scan-fabric-26.1-26.3-1.8.0.jar` | 26.1、26.1.1、26.1.2、26.2、26.3 | 25 或更新版 |
| `container-scan-fabric-1.21.11-1.8.0.jar` | 1.21.11 | 21 或更新版 |

| Minecraft | Litematica（最低版本） | MaLiLib（最低版本） |
| --- | --- | --- |
| 1.21.11 | 0.26.16 | 0.27.20 |
| 26.1、26.1.1、26.1.2 | 0.27.14 | 0.28.12 |
| 26.2 | 0.28.8 | 0.29.6 |
| 26.3 | 0.29.1 | 0.30.2 |

客户端还需要 Fabric Loader 0.19.5 或更新版，以及与当前游戏版本匹配的 Fabric API。
多人游戏默认通过 Servux 的独立实体数据通道读取容器，使用协议 2。客户端能进入服务器，并且服务器提供 `entity_data` 通道和相应访问权限时，可以跨对应的 26.x 游戏版本读取。装有 MiniHUD 时，附属 Mod 共用它的封包编解码器并单独检查同步协议。已有可用的 Litematica 同步也可作为备用。单人游戏读取本地世界。

## 使用

1. 手持木棍，按住 `Ctrl` 滚动滚轮，切到「容器获取」模式。
2. 左键选角 1，右键选角 2。进入模式或调整选区后会自动扫描，已读取的容器会在方块上方显示浮窗。
3. 移动准星对准浮窗，浮窗会置顶、放大并展开，其他浮窗的不透明度降至平时的约 60%。对应容器会显示一圈黄色细轮廓，绘制在方块和浮窗上方。双箱共用一个浮窗和一圈轮廓。切换工具模式或隐藏游戏界面会收起浮窗。
4. 按下鼠标中键打开清单。点容器查看物品图标、名称和数量。组件相同的物品堆叠会合并计数。鼠标悬停在潜影盒那一行时会显示盒内的 27 格物品及数量。
5. 在「容器类型」中用名称和图标对应的开关选择扫描目标。常见原版容器直接列出，选区内发现的受支持 Mod 容器也可启用。设置保存在 `config/litematica_container_scan.json`。

清单、物品详情和容器类型都支持滚轮浏览。在当前页底部继续向下滚动会自动翻到下一页，在页首继续向上滚动会回到上一页的末尾。

支持多子区选取，重叠位置只读一次。选中双箱任意一半时会尝试读取已加载的两半，并合并显示。扫描范围为当前客户端已加载的选区，移动到其余区块后可在清单中重新扫描。清单会区分空容器、未能读取、部分读取的双箱和战利品尚未生成。容器清单为只读。

世界浮窗随游戏的渲染帧更新。为控制绘制负担，最多同时显示视野内 48 格范围内最近的 16 个浮窗。未对准时显示一行摘要，对准时展开最多 54 格，完整内容可在清单中查看。

## 从源码构建

安装 Python 3.10+ 和 JDK 25。脚本会从 Mojang、Fabric 和 Modrinth 获取依赖，使用 Fabric Loom 为 1.21.11 重映射，并将成品放进 `build/libs`。

```powershell
py -3 build.py --java-home "D:\path\to\jdk-25"
```

默认构建通用包和 1.21.11 包。可用 `py -3 build.py 26.1-26.3` 或 `py -3 build.py 1.21.11` 单独构建。省略 `--java-home` 时优先使用 `JAVA_HOME`。
